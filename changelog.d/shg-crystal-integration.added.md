SHG retrievals through a Type I crystal everywhere a slab material is accepted: every solver, `retrieve_from_tracedata`, the bootstraps, the covariance and the thickness uncertainty take a `croak.crystals.CrystalSetup` as `material` (the thickness bootstrap gives each drawn thickness the depth nodes it needs). BBO is a built-in crystal (`croak.crystals.builtin_crystal`, optmat's Tamošauskas 2018 indices), so croak now needs `optmat[gas]>=0.10.0`, the first optmat release with BBO. Sessions describe the crystal (`crystal`, `cut_angle_deg`, `angle_mode`, `tilt_deg`, `phase_match_nm`, `polarization`, `delayed_beam`, `beam_separation_mm`), the GUI's Retrieve stage shows it as *Nonlinear crystal* and *Beam geometry* for SHG data, and the Synthetic stage can generate SHG traces through it. A crystal model refuses a marginal-corrected trace, which `TraceData.marginal_corrected` now records. A session's thickness uncertainty now raises a clear error when dispersive propagation is off, where it used to pass the unused slab material on. See [SHG FROG with a thick crystal](docs/howto/shg_crystal.md) (#24).
